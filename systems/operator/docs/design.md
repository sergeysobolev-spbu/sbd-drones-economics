# Дизайн системы "Эксплуатант БАС" (OPERATOR)

## 1. Контекст системы

Система Эксплуатант управляет парком БАС, выполняет коммерческие миссии, обеспечивая безопасность и экономическую эффективность. Основная цель - выполнение максимального количества заказов с минимальными затратами при соблюдении всех требований безопасности.

## 2. Анализ активов и рисков

### Ключевые активы

| Актив | Ценность | Неприемлемый риск |
|-------|----------|-------------------|
| Парк БАС | Критическая | Потеря управления, повреждение |
| Данные о миссиях | Высокая | Утечка коммерческой информации |
| Ключи управления | Критическая | Несанкционированное управление |
| Финансовые данные | Высокая | Прямые финансовые потери |
| Репутация | Высокая | Потеря клиентов |

### Неприемлемые риски

1. **R1**: Выполнение миссии несертифицированным БАС
2. **R2**: Нарушение плана полёта, согласованного с ОрВД
3. **R3**: Убыточная деятельность (маржа < 10%)
4. **R4**: Несанкционированный доступ к управлению БАС
5. **R5**: Утечка конфиденциальных данных клиентов

## 4. Цели безопасности

**ЦБ-OPS-1**: При любых обстоятельствах команды управления БАС отправляются только авторизованными операторами
- Механизм: Двухфакторная аутентификация, ролевая модель

**ЦБ-OPS-2**: При любых обстоятельствах миссия выполняется в границах согласованного с ОрВД плана полёта
- Механизм: Контроль траектории в реальном времени

**ЦБ-OPS-3**: При любых обстоятельствах данные о заказах доступны только авторизованным сотрудникам
- Механизм: Шифрование данных, контроль доступа

**ЦБ-OPS-4**: При любых обстоятельствах маржинальность миссии составляет не менее 10%
- Механизм: Автоматический расчёт перед принятием заказа

**ЦБ-OPS-5**: При любых обстоятельствах используются только БАС с действующими сертификатами
- Механизм: Проверка статуса перед каждым полётом

## 5. Предположения безопасности

**ПБ-OPS-1**: НУС передаёт только безопасные маршруты
**ПБ-OPS-2**: Страховые компании корректно оценивают риски
**ПБ-OPS-3**: ОрВД своевременно предоставляет разрешения
**ПБ-OPS-4**: БАС выполняют только авторизованные команды

## 6. Моделирование угроз (STRIDE)

### Spoofing (Подмена идентичности)
- T1.1: Подмена оператора при отправке команд
- T1.2: Фальсификация идентификатора БАС

### Tampering (Нарушение целостности)
- T2.1: Изменение плана миссии после согласования
- T2.2: Модификация команд управления
- T2.3: Подмена финансовых расчётов

### Repudiation (Отказ от авторства)
- T3.1: Отрицание факта отправки команды
- T3.2: Отказ от принятия заказа

### Information Disclosure (Раскрытие информации)
- T4.1: Утечка данных о маршрутах
- T4.2: Раскрытие коммерческих условий

### Denial of Service (Отказ в обслуживании)
- T5.1: Блокировка канала управления
- T5.2: Перегрузка системы заказами

### Elevation of Privilege (Повышение привилегий)
- T6.1: Получение прав администратора
- T6.2: Несанкционированное управление всем парком

## 7. Архитектура политик безопасности

### Критичные компоненты (красный цвет на диаграмме)
- **Security Monitor** - контролирует все операции
- **Command Validator** - проверяет легитимность команд

### Политики безопасности

```python
# P1: Контроль источника команд
policy_command_source = {
    "id": "P1",
    "description": "Только авторизованные операторы могут отправлять команды",
    "rules": [
        "sender.role in ['operator', 'admin']",
        "sender.authenticated == True",
        "command.target in operator.fleet"
    ]
}

# P2: Соответствие плану полёта
policy_flight_plan = {
    "id": "P2", 
    "description": "Миссия должна соответствовать утверждённому плану",
    "rules": [
        "mission.plan_approved_by == 'UTM'",
        "mission.waypoints == approved_plan.waypoints",
        "mission.time_window in approved_plan.time_window"
    ]
}

# P3: Экономическая эффективность
policy_profitability = {
    "id": "P3",
    "description": "Маржинальность не менее 10%",
    "rules": [
        "(order.price - mission.cost) / order.price >= 0.1",
        "mission.insurance_valid == True"
    ]
}

# P4: Сертификация БАС
policy_certification = {
    "id": "P4",
    "description": "Использование только сертифицированных БАС",
    "rules": [
        "uas.certificate_status == 'valid'",
        "uas.certificate_expiry > current_time"
    ]
}
```

## 8. Компоненты системы

### Fleet Manager (Управление парком)
- Отслеживание состояния всех БАС
- Выбор оптимального БАС для миссии
- Контроль готовности к полёту

### Mission Planner (Планировщик миссий)
- Получение заказов от Агрегатора
- Взаимодействие с НУС для планирования маршрута
- Регистрация миссий в ОрВД

### Business Logic (Бизнес-логика)
- Расчёт стоимости миссии
- Проверка маржинальности
- Формирование предложений

### Security Monitor (Монитор безопасности)
- Проверка всех операций на соответствие политикам
- Журналирование событий безопасности
- Блокировка нарушающих операций

## 9. Тестирование

### Покрытие тестами
- Доверенные компоненты (D0_CRITICAL): ≥ 80%
- Остальные компоненты: 30-50%

### Типы тестов
1. **Unit тесты** - изолированное тестирование компонентов
2. **Модульные тесты** - тестирование взаимодействия компонентов
3. **Интеграционные тесты** - тестирование с внешними системами
4. **E2E тесты** - сквозные сценарии

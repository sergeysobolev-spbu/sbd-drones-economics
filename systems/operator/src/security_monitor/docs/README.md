# Security Monitor Component

## Обзор

Security Monitor - критически важный компонент системы Эксплуатант, отвечающий за обеспечение безопасности и соответствие политикам. Компонент реализует принцип разделения доверенных доменов:

- **D0_CRITICAL** - минимальное ядро (SecurityMonitorCore) для критических проверок
- **D2_OPERATIONAL** - сервисный слой (SecurityMonitorService) для некритичной логики

### Разделение ответственности

#### SecurityMonitorCore (D0_CRITICAL)
- Проверка политик безопасности
- Валидация критических операций
- Ведение журнала нарушений
- Минимальн��я зависимость от внешних компонентов

#### SecurityMonitorService (D2_OPERATIONAL)
- Аудит и логирование
- Сбор и агрегация метрик
- Уведомления о нарушениях
- Интеграция с внешними системами
- Генерация отчетов

#### SecurityMonitor
- Объединение Core и Service
- Обработка сообщений через SystemBus
- Управление жизненным циклом
- Фоновые задачи (очистка, уведомления)

## Политики безопасности

### P1: Контроль источника команд
- Только авторизованные операторы могут ��тправлять команды
- Проверка роли отправителя
- Валидация разрешенных действий для роли

### P2: Защита критических операций
- Дополнительная проверка для критических действий
- Список критических операций:
  - `start_mission`
  - `abort_mission`
  - `emergency_landing`
  - `update_flight_plan`
  - `override_safety_limits`

### P3: Целостность компонентов
- Взаимодействие только с доверенными компонентами
- Проверка регистрации компонентов
- Аудит взаимодействий с недоверенными компонентами

### P4: Контроль частоты запросов
- Защита от DoS атак
- Лимиты:
  - Обычные действия: 100 запросов/минуту
  - Критические действия: 10 запросов/минуту

## API компонента

### Основные действия

#### validate_request
Валидация входящего запроса согласно политикам безопасности.

```python
{
    "action": "validate_request",
    "payload": {
        "sender_role": "operator",
        "target_component": "fleet_manager",
        "action": "reserve_uas"
    }
}
```

Ответ:
```python
{
    "allowed": true,
    "audited": false
}
```

#### check_policy
Проверка конкретной политики.

```python
{
    "action": "check_policy",
    "payload": {
        "policy_id": "P1",
        "context": {...}
    }
}
```

#### get_security_status
Получение теку��его статуса безопасности.

```python
{
    "action": "get_security_status"
}
```

Ответ:
```python
{
    "status": "operational",
    "metrics": {
        "total_requests": 1000,
        "allowed": 950,
        "denied": 30,
        "audited": 20
    },
    "violations": {...}
}
```

### Административные действия

#### get_audit_log
Получение журнала аудита с фильтрацией.

```python
{
    "action": "get_audit_log",
    "payload": {
        "start_time": 1234567890,
        "end_time": 1234567900,
        "sender_id": "operator-001",
        "action": "start_mission"
    }
}
```

#### get_security_report
Генерация комплексного отчета по безопасности.

```python
{
    "action": "get_security_report"
}
```

## Мониторинг и метрики

### Ключевые метрики

- **Request Rate** - частота запросов (req/sec)
- **Allow/Deny Rate** - процент разрешенных/отклоненных запросов
- **Violation Count** - количество нарушений по политикам
- **Audit Log Size** - размер журнала аудита

### Алерты

- Rate limit превышен для отправителя
- Критическое нарушение политики
- Высокий процент отклоненных запросов (>10%)
- Ошибки при обработке запросов

## Интеграция

### С другими компонентами

Security Monitor интегрируется со всеми компонентами системы для проверки их запросов:

- **Fleet Manager** - проверка операций с парком
- **Mission Planner** - валидация планов полетов
- **Business Logic** - контроль бизнес-операций
- **Developer Client** - проверка запросов к разработчикам
- **Regulator Client** - аудит взаимодействий с регулятором

### С Регулятором

Security Monitor отправляет уведомления Регулятору о:
- Критических нарушениях безопасности
- Изменениях статуса компонента
- Периодических отчетах по безопасности

## Разработка

### Добавление новой политики

1. Добавить политику в `_load_security_policies()` в SecurityMonitorCore
2. Реализовать логику проверки
3. Добавить тесты
4. Обновить документацию

### Расширение функциональности

При добавлении новой функциональности следуйте принципу разделения:
- Критическая логика → SecurityMonitorCore
- Некритическая логика → SecurityMonitorService

## Безопасность

### Принципы

1. **Минимальные привилегии** - компонент имеет только необходимые права
2. **Изоляция** - критическое ядро изолировано от внешних зависимостей
3. **Аудит** - все операции логируются
4. **Fail-secure** - при ошибке доступ запрещается

### Рекомендации

- Регулярно обновляйте политики безопасности
- Мониторьте аномальную активность
- Проводите периодический аудит логов
- Тестируйте сценарии атак

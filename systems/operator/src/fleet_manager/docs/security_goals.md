# Цели безопасности компонента Fleet Manager

## Обзор

Данный документ описывает цели безопасности (ЦБ) компонента Fleet Manager в соответствии с ГОСТ Р ИСО/МЭК 15408 (Common Criteria) и их реализацию в архитектуре компонента.

## Домены безопасности

### D1_TRUSTED - Доверенный домен (FleetManagerCore)
Содержит критичные функции безопасности с минимальным объемом кода.

### D2_OPERATIONAL - Операционный домен (FleetManagerService)
Содержит некритичную бизнес-логику, аналитику и интеграции.

## Цели безопасности компонента

### SG-FM-001: Контроль доступа к операциям с БАС

**Описание**: При любых обстоятельствах компонент должен обеспечивать авторизацию всех операций с БАС на основе ролей и прав доступа.

**Категория ГОСТ 72118**: Управление доступом

**Уровень**: Высокий

**Реализация**:
- Функция `authorize_uas_operation()` в FleetManagerCore
- Проверка прав оператора на выполнение операций
- Атомарность критичных операций

**Домен**: D1_TRUSTED

### SG-FM-002: Целостность состояния парка БАС

**Описание**: Компонент должен гарантировать консистентность и целостность данных о состоянии всех БАС в парке.

**Категория ГОСТ 72118**: Целостность данных

**Уровень**: Высокий

**Реализация**:
- Атомарные операции изменения состояния в FleetManagerCore
- Валидация всех обновлений состояния
- Защита от race conditions

**Домен**: D1_TRUSTED

### SG-FM-003: Контроль сертификации БАС

**Описание**: Компонент должен предотвращать использование БАС с недействительными или истекшими сертификатами.

**Категория ГОСТ 72118**: Аутентичность

**Уровень**: Высокий

**Реализация**:
- Проверка `certificate_valid` и `certificate_expiry`
- Блокировка операций для несертифицированных БАС
- Мониторинг сроков действия сертификатов

**Домен**: D1_TRUSTED

### SG-FM-004: Аудит операций с БАС

**Описание**: Все операции с БАС должны регистрироваться для последующего анализа и расследования инцидентов.

**Категория ГОСТ 72118**: Регистрация и учет

**Уровень**: Средний

**Реализация**:
- Логирование всех операций в FleetManagerService
- Сохранение истории операций
- Метрики использования

**Домен**: D2_OPERATIONAL

### SG-FM-005: Доступность парка БАС

**Описание**: Компонент должен обеспечивать оптимальное распределение БАС и предотвращать их блокировку.

**Категория ГОСТ 72118**: Доступность

**Уровень**: Средний

**Реализация**:
- Таймауты резервирований
- Автоматическое освобождение БАС
- Мониторинг доступности

**Домен**: D2_OPERATIONAL

## Обоснование минимизации доверенных доменов

### Код в D1_TRUSTED (FleetManagerCore)
- **Объем**: ~250 строк кода
- **Функции**: Только критичные проверки безопасности
- **Обоснование**: Минимальная поверхность атаки, простота верификации

### Код в D2_OPERATIONAL (FleetManagerService)
- **Объем**: ~800 строк кода
- **Функции**: Бизнес-логика, оптимизации, интеграции
- **Обоснование**: Некритичный код изолирован от доверенного домена

### Преимущества разделения
1. Уменьшение TCB (Trusted Computing Base) на 75%
2. Упрощение формальной верификации критичного кода
3. Изоляция потенциальных уязвимостей в некритичном коде
4. Возможность независимого обновления доменов

## Механизмы реализации

### Технические меры
1. **Изоляция доменов**: Разделение на независимые классы
2. **Чистые функции**: Критичные функции без побочных эффектов
3. **Типизация**: Строгая типизация всех интерфейсов
4. **Валидация**: Проверка всех входных данных

### Организационные меры
1. **Code review**: Обязательная проверка изменений в D1_TRUSTED
2. **Тестирование**: 100% покрытие критичного кода
3. **Мониторинг**: Непрерывный контроль метрик безопасности

## Соответствие стандартам

### ГОСТ Р ИСО/МЭК 15408
- Функциональные требования безопасности (SFR)
- Требования доверия к безопасности (SAR)
- Профиль защиты (PP)

### ГОСТ Р 59453-2021
- Доверенная среда функционирования
- Изоляция компонентов
- Контроль информационных потоков

## Метрики безопасности

1. **Размер TCB**: < 20% от общего кода
2. **Покрытие тестами TCB**: > 95%
3. **Сложность функций TCB**: < 10 (цикломатическая)
4. **Время отклика проверок**: < 10 мс

# Доработанное верхнеуровневое описание прототипа технико-экономической модели взаимодействия участников рынка применения автономных дронов

## Краткое описание проекта

Прототип представляет собой учебную систему моделирования экономических взаимодействий участников рынка беспилотных авиационных систем (БАС) с применением принципов конструктивной информационной безопасности (КИБ) согласно ГОСТ Р 72118-2025. Система демонстрирует практическое применение методологии проектирования защищённых систем через реализацию многодоменной архитектуры с контролируемым взаимодействием компонентов.

## Цели и задачи прототипа

### Основные цели:
1. **Образовательная** - обучение студентов принципам проектирования систем с конструктивной ИБ
2. **Демонстрационная** - показать практическое применение ГОСТ Р 72118-2025
3. **Исследовательская** - моделирование экономических стимулов внедрения КИБ
4. **Методологическая** - создание шаблонов проектирования СКИБ

### Ключевые задачи:
- Реализация многодоменной архитектуры с изоляцией компонентов
- Демонстрация принципа минимизации доверенной вычислительной базы (TCB)
- Контроль всех междоменных взаимодействий через единую точку медиации
- Экономическое моделирование стимулов безопасной эксплуатации БАС
- Обеспечение полной наблюдаемости и аудируемости системы

## Архитектурные принципы

### 1. Доменная модель безопасности

Система использует иерархическую модель доменов безопасности с различными уровнями доверия:

**D0_CRITICAL** (Критически важные для безопасности):
- **D0.1_MEDIATION**: Междоменная медиация
  - `interdomain-gateway` - контроль всех междоменных взаимодействий
  - `audit-log` - неизменяемый журнал событий
- **D0.2_POLICY**: Управление политиками
  - `policy-repository` - хранилище политик безопасности
  - `policy-validator` - валидация политик
- **D0.3_CRYPTO**: Криптографические сервисы
  - `certificate-manager` - управление сертификатами
  - `signature-service` - создание и проверка подписей

**D1_TRUSTED** (Доверенные операционные):
- **D1.1_FLIGHT_SAFETY**: Безопасность полётов
  - `uas-safety-monitor` - мониторинг безопасности БАС
  - `collision-avoidance` - предотвращение столкновений
- **D1.2_MISSION_CONTROL**: Управление миссиями
  - `mission-validator` - валидация миссий
  - `route-optimizer` - оптимизация маршрутов
- **D1.3_COMPLIANCE**: Соответствие требованиям
  - `regulation-checker` - проверка соответствия регуляциям
  - `insurance-validator` - валидация страховых полисов

**D2_OPERATIONAL** (Операционные):
- **D2.1_BUSINESS**: Бизнес-логика
  - `ops-core` - основная бизнес-логика эксплуатанта
  - `pricing-engine` - расчёт стоимости услуг
- **D2.2_INTEGRATION**: Интеграция
  - `external-api-gateway` - интеграция с внешними API
  - `data-transformer` - преобразование данных

**D3_UNTRUSTED** (Недоверенные):
- **D3.1_EXTERNAL**: Внешние сервисы
  - `aggregator-sim` - симулятор агрегатора
  - `customer-portal` - портал заказчика
- **D3.2_SIMULATION**: Симуляция
  - `sitl-adapter` - адаптер SITL
  - `environment-sim` - симулятор окружения

### 2. Принципы взаимодействия

1. **Принудительная медиация**: Все междоменные взаимодействия проходят через `interdomain-gateway`
2. **Минимальные привилегии**: Каждый компонент имеет доступ только к необходимым топикам
3. **Валидация на границах**: Проверка схем, подписей, временных меток
4. **Идемпотентность**: Защита от повторной обработки сообщений
5. **Аудит всех решений**: Логирование разрешений и отказов

### 3. Минимизация TCB

В доверенную вычислительную базу входят только:
- Конфигурация брокера (ACL, TLS)
- `interdomain-gateway` (валидация и маршрутизация)
- `ops-policy-enforcer` (применение политик безопасности)
- `audit-log` (целостность журнала)

## Технологический стек

### Основные технологии:
- **Языки**: Python (основной), Go/Rust (опционально)
- **Брокеры**: Kafka (этап 1 - симуляция), Mosquitto MQTT (этап 2 - физические дроны)
- **Контейнеризация**: Docker, docker-compose
- **Оркестрация**: Makefile
- **Тестирование**: pytest, pytest-cov
- **Документация**: Markdown, PlantUML, draw.io
- **Мониторинг**: ELK stack (Elasticsearch, Logstash, Kibana)

### Форматы данных:
- **Сообщения**: JSON с единым envelope (CloudEvents-подобный)
- **Схемы**: JSON Schema для валидации
- **Журналы**: JSONL (JSON Lines)
- **Телеметрия**: Parquet или CSV

## Экономическая модель

### Участники и их роли:

1. **Регулятор**:
   - Сертификация прошивок БАС
   - Ведение реестра дронов
   - Контроль соблюдения целей безопасности
   - Взимание платы за услуги

2. **Разработчик БАС**:
   - Проектирование с учётом целей безопасности
   - Сертификация прошивок
   - Производство и регистрация БАС

3. **Эксплуатант**:
   - Закупка сертифицированных БАС
   - Выполнение коммерческих миссий
   - Соблюдение политик безопасности
   - Норма прибыли ≥10%

4. **Страховая компания**:
   - Оценка рисков на основе целей безопасности
   - Страхование миссий
   - Контроль соблюдения условий

5. **ОрВД БАС**:
   - Авторизация миссий
   - Контроль воздушного пространства
   - Управление конфликтами
   - Динамические ограничения

6. **Агрегатор**:
   - Приём заказов от клиентов
   - Распределение между эксплуатантами
   - Контроль выполнения

7. **Дронопорт**:
   - Физическое размещение БАС
   - Межполётное обслуживание
   - Контроль доступа

### Экономические стимулы:
- Сертифицированные БАС получают доступ к коммерческим миссиям
- Страховые премии ниже для безопасных систем
- Штрафы за нарушение целей безопасности
- Прозрачная цепочка ответственности

## Сценарии использования

### 1. Опрыскивание полей (AGR)
- Контроль зон распыления
- Учёт расхода химикатов
- Запрет распыления вне целевых участков
- Экологическая безопасность

### 2. Инспекция инфраструктуры (INSP)
- Соблюдение безопасных дистанций
- Сбор данных с сенсоров
- Контроль маршрута облёта
- Обработка динамических ограничений

### 3. Доставка грузов (CARGO)
- Контроль цепочки владения
- Защита от несанкционированного доступа
- Страхование ценных грузов
- Подтверждение доставки

## Этапы реализации

### Этап 1: Симуляция (Kafka)
- Полностью виртуальная среда
- Все компоненты в Docker
- Сквозное тестирование
- Демонстрация принципов КИБ

### Этап 2: Интеграция с физическими дронами (MQTT)
- 20-40 реальных БАС
- Команды почти в реальном времени
- mTLS для аутентификации
- Полевые испытания

## Метрики и KPI

### Безопасность:
- Время обнаружения нарушений ≤ 5 сек
- Время реакции на отзыв сертификата ≤ 5 сек
- Нулевая толерантность к нарушениям геозон
- 100% аудируемость событий

### Производительность:
- Задержка команд ≤ 500 мс (лаборатория)
- Пропуски телеметрии ≤ 5 сек
- Масштабируемость до 40 БАС

### Качество:
- Покрытие тестами TCB ≥ 80%
- Покрытие недоверенного кода ≥ 30%
- Документированность API 100%

# Анализ безопасности систем с применением кибериммунного подхода и ГОСТ Р 72118-2025

## Методология анализа

Для каждой системы проводится:
1. **Анализ активов** - выявление ценных ресурсов и потенциальных ущербов
2. **Моделирование угроз** - идентификация векторов атак и уязвимостей
3. **Формулировка целей безопасности** - инварианты, которые система должна поддерживать
4. **Определение предположений безопасности** - условия окружения для корректной работы
5. **Проектирование архитектуры** - минимизация TCB и изоляция критичных компонентов

## 1. Система "Регулятор" (REGULATOR)

### Контекст системы
Регулятор является центральным доверенным узлом экосистемы, отвечающим за сертификацию, регистрацию и контроль соблюдения требований безопасности.

### Анализ активов

| Актив | Ценность | Потенциальный ущерб при компрометации |
|-------|----------|---------------------------------------|
| Реестр сертификатов | Критическая | Полная потеря доверия к экосистеме |
| Приватные ключи подписи | Критическая | Возможность выпуска поддельных сертификатов |
| База данных БАС | Высокая | Нарушение прослеживаемости, незаконная эксплуатация |
| Журналы аудита | Высокая | Невозможность расследования инцидентов |
| Политики сертификации | Средняя | Снижение уровня безопасности экосистемы |

### Моделирование угроз (STRIDE)

**Spoofing (Подмена идентичности)**
- T1.1: Подмена запросов от разработчиков БАС
- T1.2: Фальсификация идентификаторов систем

**Tampering (Нарушение целостности)**
- T2.1: Модификация записей в реестре сертификатов
- T2.2: Изменение статуса сертификата без авторизации
- T2.3: Подмена результатов проверки покрытия тестами

**Repudiation (Отказ от авторства)**
- T3.1: Отрицание факта выдачи/отзыва сертификата
- T3.2: Отказ от регистрации БАС

**Information Disclosure (Раскрытие информации)**
- T4.1: Утечка приватных ключей подписи
- T4.2: Несанкционированный доступ к данным о проверках

**Denial of Service (Отказ в обслуживании)**
- T5.1: Перегрузка сервиса проверки сертификатов
- T5.2: Блокировка процесса сертификации

**Elevation of Privilege (Повышение привилегий)**
- T6.1: Получение прав на отзыв любых сертификатов
- T6.2: Несанкционированная выдача сертификатов

### Цели безопасности (конструктивная форма)

**ЦБ-REG-1**: При любых обстоятельствах сертификаты безопасности выдаются только после успешной проверки всех требований
- Актив: Процесс сертификации
- Ущерб: Компрометация всей экосистемы
- Механизм: Автоматизированная проверка покрытия тестами, наличия целей безопасности

**ЦБ-REG-2**: При любых обстоятельствах выданные сертификаты содержат криптографически защищённую подпись Регулятора
- Актив: Подлинность сертификатов
- Ущерб: Эксплуатация небезопасных систем
- Механизм: HSM для хранения ключей, алгоритм ГОСТ Р 34.10-2018

**ЦБ-REG-3**: При любых обстоятельствах актуальный статус сертификата доступен для проверки в течение 5 секунд
- Актив: Доступность сервиса проверки
- Ущерб: Использование скомпрометированных систем
- Механизм: Репликация базы данных, кеширование

**ЦБ-REG-4**: При любых обстоятельствах все операции с сертификатами записываются в неизменяемый журнал
- Актив: Журнал аудита
- Ущерб: Невозможность расследования инцидентов
- Механизм: Append-only log с хеш-цепочкой

**ЦБ-REG-5**: При любых обстоятельствах информация о сертифицированных топиках участников актуальна и подписана
- Актив: Реестр топиков
- Ущерб: Нарушение маршрутизации сообщений
- Механизм: Версионирование, цифровая подпись

### Предположения безопасности

**ПБ-REG-1**: Инфраструктура PKI корректно настроена и защищена

**ПБ-REG-2**: Персонал Регулятора прошёл проверку и обучение

**ПБ-REG-3**: Физический доступ к серверам ограничен

**ПБ-REG-4**: Резервное копирование выполняется регулярно

## 2. Система "Эксплуатант БАС" (OPERATOR)

### Контекст системы
Эксплуатант управляет парком БАС, выполняет коммерческие миссии, обеспечивая безопасность и экономическую эффективность.

### Анализ активов

| Актив | Ценность | Потенциальный ущерб |
|-------|----------|---------------------|
| Парк БАС | Критическая | Финансовые потери, невыполнение обязательств |
| Данные о миссиях | Высокая | Нарушение конфиденциальности клиентов |
| Ключи управления БАС | Критическая | Потеря контроля над БАС, аварии |
| Финансовые данные | Высокая | Прямые финансовые потери |
| Репутация | Высокая | Потеря клиентов и доходов |

### Моделирование угроз

**Векторы атак на управление БАС:**
- T1: Перехват управления БАС злоумышленником
- T2: Подмена команд миссии
- T3: Блокировка легитимных команд (DoS)

**Угрозы бизнес-логике:**
- T4: Манипуляция ценообразованием
- T5: Фальсификация отчётов о выполнении
- T6: Кража коммерческой информации

**Угрозы соответствию:**
- T7: Запуск несертифицированных БАС
- T8: Нарушение условий страхования
- T9: Полёты без разрешения ОрВД

### Цели безопасности (конструктивная форма)

**ЦБ-OPS-1**: При любых обстоятельствах команды управления БАС отправляются только авторизованными операторами
- Актив: Канал управления
- Ущерб: Потеря контроля, аварии
- Механизм: Двухфакторная аутентификация, ролевая модель

**ЦБ-OPS-2**: При любых обстоятельствах миссия выполняется в границах согласованного с ОрВД плана полёта
- Актив: Соответствие плану
- Ущерб: Нарушение договорных обязательств
- Механизм: Контроль траектории в реальном времени

**ЦБ-OPS-3**: При любых обстоятельствах данные о заказах доступны только авторизованным сотрудникам
- Актив: Конфиденциальность
- Ущерб: Потеря доверия, иски
- Механизм: Шифрование данных, контроль доступа

**ЦБ-OPS-4**: При любых обстоятельствах маржинальность миссии составляет не менее 10%
- Актив: Экономическая устойчивость
- Ущерб: Убыточная деятельность
- Механизм: Автоматический расчёт перед принятием заказа

**ЦБ-OPS-5**: При любых обстоятельствах используются только БАС с действующими сертификатами
- Актив: Легальность операций
- Ущерб: Штрафы, отзыв лицензии
- Механизм: Проверка статуса перед каждым полётом

### Предположения безопасности

**ПБ-OPS-1**: БАС имеют встроенные механизмы безопасности
**ПБ-OPS-2**: Страховые компании корректно оценивают риски
**ПБ-OPS-3**: ОрВД предоставляет актуальную информацию
**ПБ-OPS-4**: Сетевая инфраструктура защищена

## 3. Система "ОрВД БАС" (UTM - UAS Traffic Management)

### Контекст системы
Система управления воздушным движением БАС обеспечивает безопасность воздушного пространства через авторизацию полётов и предотвращение конфликтов.

### Анализ активов

| Актив | Ценность | Потенциальный ущерб |
|-------|----------|---------------------|
| База активных полётов | Критическая | Столкновения БАС |
| Геозоны и ограничения | Критическая | Нарушение запретных зон |
| Система деконфликтации | Критическая | Аварии в воздухе |
| Данные телеметрии | Высокая | Потеря ситуационной осведомлённости |

### Моделирование угроз

**Безопасность воздушного пространства:**
- T1: Фальсификация разрешений на полёт
- T2: Сокрытие реального положения БАС
- T3: Игнорирование запретных зон
- T4: Преднамеренное создание конфликтов

**Операционные угрозы:**
- T5: Перегрузка системы ложными запросами
- T6: Задержка критичных команд
- T7: Потеря связи с БАС

### Цели безопасности (конструктивная форма)

**ЦБ-UTM-1**: При любых обстоятельствах минимальная дистанция между БАС составляет не менее 50 метров
- Актив: Безопасность воздушного движения
- Ущерб: Столкновения, человеческие жертвы
- Механизм: Алгоритм деконфликтации в реальном времени

**ЦБ-UTM-2**: При любых обстоятельствах БАС находятся вне активных запретных зон
- Актив: Соблюдение ограничений
- Ущерб: Нарушение безопасности объектов
- Механизм: Динамические геозоны, автоматическая корректировка

**ЦБ-UTM-3**: При любых обстоятельствах разрешения выдаются только БАС с действующими сертификатами
- Актив: Контроль допуска
- Ущерб: Небезопасные полёты
- Механизм: Интеграция с Регулятором, кеш статусов

**ЦБ-UTM-4**: При любых обстоятельствах команды экстренной посадки доставляются БАС в течение 5 секунд
- Актив: Экстренное управление
- Ущерб: Эскалация инцидентов
- Механизм: Приоритетная очередь, резервные каналы

**ЦБ-UTM-5**: При любых обстоятельствах телеметрия всех активных БАС обновляется не реже 1 Гц
- Актив: Ситуационная осведомлённость
- Ущерб: Потеря контроля над воздушным пространством
- Механизм: Мониторинг потоков данных, алерты

### Предположения безопасности

**ПБ-UTM-1**: БАС передают достоверную телеметрию
**ПБ-UTM-2**: Связь с БАС имеет ограниченную задержку
**ПБ-UTM-3**: Геоданные актуальны и точны
**ПБ-UTM-4**: Операторы следуют командам системы

## 4. Система "Страховая компания" (INSURER)

### Контекст системы
Страховая компания оценивает риски и предоставляет финансовую защиту для операций БАС.

### Анализ активов

| Актив | Ценность | Потенциальный ущерб |
|-------|----------|---------------------|
| Модели оценки рисков | Критическая | Неверная оценка, убытки |
| База данных инцидентов | Высокая | Потеря истории для анализа |
| Финансовые резервы | Критическая | Невозможность выплат |
| Алгоритмы ценообразования | Высокая | Неконкурентные цены |

### Моделирование угроз

**Финансовые угрозы:**
- T1: Мошенничество со страховыми случаями
- T2: Манипуляция данными для снижения премий
- T3: Сокрытие реальных рисков

**Операционные угрозы:**
- T4: Задержка выплат по техническим причинам
- T5: Неверная классификация рисков
- T6: Утечка конфиденциальных данных клиентов

### Цели безопасности (конструктивная форма)

**ЦБ-INS-1**: При любых обстоятельствах страховая премия рассчитывается на основе актуальных данных о рисках
- Актив: Адекватность оценки
- Ущерб: Убытки от недооценки рисков
- Механизм: ML-модели, исторические данные

**ЦБ-INS-2**: При любых обстоятельствах выплаты производятся только при подтверждённых страховых случаях
- Актив: Защита от мошенничества
- Ущерб: Финансовые потери
- Механизм: Многоуровневая проверка, интеграция с журналами

**ЦБ-INS-3**: При любых обстоятельствах данные клиентов хранятся в зашифрованном виде
- Актив: Конфиденциальность
- Ущерб: Репутационные риски, иски
- Механизм: AES-256, управление ключами

**ЦБ-INS-4**: При любых обстоятельствах нарушения целей безопасности сообщаются Регулятору в течение 1 часа
- Актив: Обратная связь
- Ущерб: Системные риски экосистемы
- Механизм: Автоматическая отправка отчётов

### Предположения безопасности

**ПБ-INS-1**: Данные от Регулятора достоверны
**ПБ-INS-2**: Отчёты об инцидентах не фальсифицированы
**ПБ-INS-3**: Финансовая инфраструктура защищена

## 5. Система "БАС" (UAS - Unmanned Aircraft System)

### Контекст системы
Беспилотная авиационная система выполняет полётные миссии, обеспечивая безопасность и соблюдение всех ограничений.

### Анализ активов

| Актив | Ценность | Потенциальный ущерб |
|-------|----------|---------------------|
| Полётный контроллер | Критическая | Потеря управления, крушение |
| Модуль безопасности | Критическая | Нарушение ограничений |
| Полезная нагрузка | Высокая | Невыполнение миссии |
| Навигационные данные | Критическая | Потеря ориентации |

### Моделирование угроз

**Угрозы безопасности полёта:**
- T1: Подмена навигационных данных (GPS spoofing)
- T2: Перехват управления (hijacking)
- T3: Вмешательство в работу автопилота
- T4: Отключение модуля безопасности

**Угрозы миссии:**
- T5: Несанкционированный доступ к грузу
- T6: Изменение маршрута полёта
- T7: Преждевременный сброс груза

### Цели безопасности (конструктивная форма)

**ЦБ-UAS-1**: При любых обстоятельствах полёты выполняются в пределах авторизованных коридоров и эшелонов
- Актив: Соблюдение воздушного пространства
- Ущерб: Нарушение воздушного пространства
- Механизм: Геозоны в полётном контроллере

**ЦБ-UAS-2**: При любых обстоятельствах выполняются только авторизованные полётные задания
- Актив: Целостность управления
- Ущерб: Потеря контроля
- Механизм: Проверка цифровой подписи миссии

**ЦБ-UAS-3**: При любых обстоятельствах в наземные службы передаётся аутентичный идентификатор БАС
- Актив: Идентификация
- Ущерб: Невозможность отслеживания
- Механизм: Аппаратный идентификатор, защита от подмены

**ЦБ-UAS-4**: При любых обстоятельствах полёты выполняются с включёнными проблесковыми маяками
- Актив: Визуальная идентификация
- Ущерб: Столкновения с пилотируемыми ВС
- Механизм: Автоматическое включение при взлёте

**ЦБ-UAS-5**: При любых обстоятельствах передаются достоверные данные о местоположении
- Актив: Навигационная целостность
- Ущерб: Потеря ситуационной осведомлённости
- Механизм: Мультисенсорная навигация, защита от spoofing

**ЦБ-UAS-6**: При любых обстоятельствах все критичные события записываются в защищённый журнал
- Актив: Аудит полёта
- Ущерб: Невозможность расследования инцидентов
- Механизм: Append-only storage, криптографическая защита

**ЦБ-UAS-7**: При любых обстоятельствах при потере связи более 30 секунд инициируется аварийная посадка
- Актив: Безопасность при отказах
- Ущерб: Неконтролируемый полёт
- Механизм: Независимый таймер, автономная логика

### Предположения безопасности

**ПБ-UAS-1**: Полётный контроллер изолирован от внешних интерфейсов
**ПБ-UAS-2**: Криптографические ключи защищены аппаратно
**ПБ-UAS-3**: Датчики предоставляют достоверные данные
**ПБ-UAS-4**: Резервный канал связи доступен

## Общие принципы обеспечения безопасности

### 1. Минимизация TCB (Trusted Computing Base)
- Критичные для безопасности функции выносятся в минимальные изолированные компоненты
- Код TCB проходит формальную верификацию где возможно
- Покрытие тестами TCB ≥ 80%

### 2. Принцип наименьших привилегий
- Каждый компонент имеет доступ только к необходимым ресурсам
- Межкомпонентное взаимодействие строго регламентировано
- Временные повышения привилегий журналируются

### 3. Защита в глубину
- Множественные уровни контроля
- Независимые механизмы безопасности
- Fail-secure поведение при отказах

### 4. Прозрачность и аудируемость
- Все критичные операции журналируются
- Журналы защищены от модификации
- Возможность независимого аудита

### 5. Криптографическая защита
- Использование проверенных алгоритмов
- Регулярная ротация ключей
- Аппаратная защита критичных ключей

## Метрики эффективности защиты

| Метрика | Целевое значение | Измерение |
|---------|------------------|-----------|
| Время обнаружения нарушения ЦБ | < 5 сек | Мониторинг |
| Время реакции на инцидент | < 30 сек | Тесты |
| Доля ложных срабатываний | < 1% | Статистика |
| Покрытие угроз контрмерами | > 95% | Анализ |
| Доступность критичных сервисов | > 99.9% | Мониторинг |

## Заключение

Применение кибериммунного подхода и требований ГОСТ Р 72118-2025 позволяет создать экосистему БАС с встроенной безопасностью, где:

1. Каждая система имеет чётко определённые цели безопасности
2. Архитектура минимизирует поверхность атаки
3. Критичные компоненты изолированы и защищены
4. Нарушения быстро обнаруживаются и блокируются
5. Экономические стимулы поощряют безопасное поведение

Это создаёт основу для безопасной коммерческой эксплуатации БАС в масштабах национальной экономики.

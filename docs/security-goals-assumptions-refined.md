# Доработанные цели и предположения безопасности систем

## Принципы формулировки целей безопасности

1. **Конструктивная форма** - цели формулируются как инварианты, которые система поддерживает
2. **Связность** - предположения безопасности одной системы являются целями безопасности смежных систем
3. **Полнота покрытия** - отсутствие провисания ответственности за критические активы
4. **Измеримость** - возможность проверки выполнения цели

## 1. Система "Регулятор" (REGULATOR)

### Цели безопасности

**ЦБ-REG-1**: При любых обстоятельствах сертификаты безопасности выдаются только после успешной проверки всех требований
- Актив: Процесс сертификации
- Механизм: Автоматизированная проверка покрытия тестами, наличия целей безопасности

**ЦБ-REG-2**: При любых обстоятельствах выданные сертификаты содержат криптографически защищённую подпись Регулятора
- Актив: Подлинность сертификатов
- Механизм: HSM для хранения ключей, алгоритм ГОСТ Р 34.10-2018

**ЦБ-REG-3**: При любых обстоятельствах актуальный статус сертификата доступен для проверки в течение 5 секунд
- Актив: Доступность сервиса проверки
- Механизм: Репликация базы данных, кеширование

**ЦБ-REG-4**: При любых обстоятельствах все операции с сертификатами записываются в неизменяемый журнал
- Актив: Аудит операций
- Механизм: Append-only log с хеш-цепочкой

**ЦБ-REG-5**: При любых обстоятельствах информация о сертифицированных топиках участников актуальна и подписана
- Актив: Реестр топиков
- Механизм: Версионирование, цифровая подпись

### Предположения безопасности

**ПБ-REG-1**: Инфраструктура PKI защищена от компрометации
**ПБ-REG-2**: Персонал Регулятора действует в соответствии с регламентами
**ПБ-REG-3**: Время системы синхронизировано с эталоном (NTP)
**ПБ-REG-4**: Канал связи с HSM защищён от перехвата

## 2. Система "Эксплуатант БАС" (OPERATOR)

### Цели безопасности

**ЦБ-OPS-1**: При любых обстоятельствах команды управления БАС отправляются только авторизованными операторами
- Актив: Канал управления
- Механизм: Двухфакторная аутентификация, ролевая модель

**ЦБ-OPS-2**: При любых обстоятельствах миссия выполняется в границах согласованного с ОрВД плана полёта
- Актив: Соответствие плану
- Механизм: Контроль траектории в реальном времени

**ЦБ-OPS-3**: При любых обстоятельствах данные о заказах доступны только авторизованным сотрудникам
- Актив: Конфиденциальность
- Механизм: Шифрование данных, контроль доступа

**ЦБ-OPS-4**: При любых обстоятельствах маржинальность миссии составляет не менее 10%
- Актив: Экономическая устойчивость
- Механизм: Автоматический расчёт перед принятием заказа

**ЦБ-OPS-5**: При любых обстоятельствах используются только БАС с действующими сертификатами
- Актив: Легальность операций
- Механизм: Проверка статуса перед каждым полётом

### Предположения безопасности

**ПБ-OPS-1**: НУС передаёт только безопасные маршруты (→ ЦБ-GCS-1)
**ПБ-OPS-2**: Страховые компании корректно оценивают риски (→ ЦБ-INS-1)
**ПБ-OPS-3**: ОрВД своевременно предоставляет разрешения (→ ЦБ-UTM-3)
**ПБ-OPS-4**: БАС выполняют только авторизованные команды (→ ЦБ-UAS-2)

## 3. Система "ОрВД БАС" (UTM)

### Цели безопасности

**ЦБ-UTM-1**: При любых обстоятельствах минимальная дистанция между БАС составляет не менее 50 метров
- Актив: Безопасность воздушного движения
- Механизм: Алгоритм деконфликтации в реальном времени

**ЦБ-UTM-2**: При любых обстоятельствах БАС находятся вне активных запретных зон
- Актив: Соблюдение ограничений
- Механизм: Динамические геозоны, автоматическая корректировка

**ЦБ-UTM-3**: При любых обстоятельствах разрешения выдаются только БАС с действующими сертификатами
- Актив: Контроль допуска
- Механизм: Интеграция с Регулятором, кеш статусов

**ЦБ-UTM-4**: При любых обстоятельствах команды экстренной посадки доставляются БАС в течение 5 секунд
- Актив: Экстренное управление
- Механизм: Приоритетная очередь, резервные каналы

**ЦБ-UTM-5**: При любых обстоятельствах телеметрия всех активных БАС обновляется не реже 1 Гц
- Актив: Ситуационная осведомлённость
- Механизм: Мониторинг потоков данных, алерты

### Предположения безопасности

**ПБ-UTM-1**: БАС передают достоверные координаты (→ ЦБ-UAS-5)
**ПБ-UTM-2**: Эксплуатанты регистрируют все миссии (→ ЦБ-OPS-2)
**ПБ-UTM-3**: Дронопорты выполняют команды блокировки (→ ЦБ-DRP-2)
**ПБ-UTM-4**: Каналы связи обеспечивают требуемую латентность

## 4. Система "Страховая компания" (INSURER)

### Цели безопасности

**ЦБ-INS-1**: При любых обстоятельствах страховая премия рассчитывается на основе актуальных данных о рисках
- Актив: Адекватность оценки
- Механизм: ML-модели, исторические данные

**ЦБ-INS-2**: При любых обстоятельствах выплаты производятся только при подтверждённых страховых случаях
- Актив: Защита от мошенничества
- Механизм: Многоуровневая проверка, интеграция с журналами

**ЦБ-INS-3**: При любых обстоятельствах данные клиентов хранятся в зашифрованном виде
- Актив: Конфиденциальность
- Механизм: AES-256, управление ключами

**ЦБ-INS-4**: При любых обстоятельствах нарушения целей безопасности сообщаются Регулятору в течение 1 часа
- Актив: Обратная связь
- Механизм: Автоматическая отправка отчётов

### Предположения безопасности

**ПБ-INS-1**: Регулятор предоставляет актуальные данные о сертификатах (→ ЦБ-REG-3)
**ПБ-INS-2**: Эксплуатанты предоставляют достоверные данные о миссиях (→ ЦБ-OPS-2)
**ПБ-INS-3**: Журналы БАС не подвержены модификации (→ ЦБ-UAS-6)

## 5. Система "БАС" (UAS)

### Цели безопасности

**ЦБ-UAS-1**: При любых обстоятельствах полёты выполняются в пределах авторизованных коридоров и эшелонов
- Актив: Соблюдение воздушного пространства
- Механизм: Геозоны в полётном контроллере

**ЦБ-UAS-2**: При любых обстоятельствах выполняются только авторизованные полётные задания
- Актив: Целостность управления
- Механизм: Проверка цифровой подписи миссии

**ЦБ-UAS-3**: При любых обстоятельствах в наземные службы передаётся аутентичный идентификатор БАС
- Актив: Идентификация
- Механизм: Аппаратный идентификатор, защита от подмены

**ЦБ-UAS-4**: При любых обстоятельствах полёты выполняются с включёнными проблесковыми маяками
- Актив: Визуальная идентификация
- Механизм: Автоматическое включение при взлёте

**ЦБ-UAS-5**: При любых обстоятельствах передаются достоверные данные о местоположении
- Актив: Навигационная целостность
- Механизм: Мультисенсорная навигация, защита от spoofing

**ЦБ-UAS-6**: При любых обстоятельствах все критичные события записываются в защищённый журнал
- Актив: Аудит полёта
- Механизм: Append-only storage, криптографическая защита

**ЦБ-UAS-7**: При любых обстоятельствах при потере связи более 30 секунд инициируется аварийная посадка
- Актив: Безопасность при отказах
- Механизм: Независимый таймер, автономная логика

### Предположения безопасности

**ПБ-UAS-1**: ОрВД предоставляет актуальные геозоны (→ ЦБ-UTM-2)
**ПБ-UAS-2**: НУС передаёт корректные полётные задания (→ ЦБ-GCS-1)
**ПБ-UAS-3**: Навигационные сигналы не подвержены критическим помехам
**ПБ-UAS-4**: Полётный контроллер функционирует корректно

## 6. Система "Агрегатор" (AGGREGATOR)

### Цели безопасности

**ЦБ-AGG-1**: При любых обстоятельствах условия заказа после подтверждения остаются неизменными
- Актив: Целостность транзакций
- Механизм: Блокировка изменений, версионирование

**ЦБ-AGG-2**: При любых обстоятельствах алгоритм распределения заказов работает без предпочтений
- Актив: Справедливость
- Механизм: Прозрачные критерии, аудит решений

**ЦБ-AGG-3**: При любых обстоятельствах персональные данные передаются только с согласия клиента
- Актив: Приватность
- Механизм: Управление согласиями, минимизация данных

**ЦБ-AGG-4**: При любых обстоятельствах финансовые транзакции проводятся через защищённые каналы
- Актив: Финансовая безопасность
- Механизм: PCI DSS compliance, токенизация

### Предположения безопасности

**ПБ-AGG-1**: Эксплуатанты предоставляют достоверные предложения (→ ЦБ-OPS-4)
**ПБ-AGG-2**: Клиенты указывают корректные требования безопасности
**ПБ-AGG-3**: Платёжная система обеспечивает защиту транзакций

## 7. Система "Дронопорт" (DRONEPORT)

### Цели безопасности

**ЦБ-DRP-1**: При любых обстоятельствах доступ к БАС имеют только авторизованные лица и системы
- Актив: Физическая безопасность
- Механизм: Биометрический контроль, видеонаблюдение

**ЦБ-DRP-2**: При любых обстоятельствах команда "План Ковёр" блокирует все вылеты в течение 10 секунд
- Актив: Экстренная блокировка
- Механизм: Физические барьеры, отключение питания

**ЦБ-DRP-3**: При любых обстоятельствах одновременно может выполняться только одна операция взлёта/посадки
- Актив: Безопасность манёвров
- Механизм: Семафоры, визуальная сигнализация

**ЦБ-DRP-4**: При любых обстоятельствах зарядка БАС выполняется с соблюдением параметров безопасности
- Актив: Сохранность оборудования
- Механизм: Контроль тока/напряжения, температурный мониторинг

### Предположения безопасности

**ПБ-DRP-1**: Физический периметр защищён от проникновения
**ПБ-DRP-2**: ОрВД своевременно передаёт команды блокировки (→ ЦБ-UTM-4)
**ПБ-DRP-3**: БАС соблюдают протоколы взлёта/посадки (→ ЦБ-UAS-1)
**ПБ-DRP-4**: Электросеть обеспечивает стабильное питание

## 8. Система "НУС" (GCS)

### Цели безопасности

**ЦБ-GCS-1**: При любых обстоятельствах рассчитанные маршруты безопасны и выполнимы
- Актив: Качество планирования
- Механизм: Валидация по цифровой карте, проверка ограничений БАС

**ЦБ-GCS-2**: При любых обстоятельствах управление БАС осуществляется только в автономном режиме
- Актив: Исключение человеческого фактора
- Механизм: Блокировка ручного управления, кроме экстренных команд

**ЦБ-GCS-3**: При любых обстоятельствах предполётные проверки выполняются по полному чек-листу
- Актив: Готовность к полёту
- Механизм: Автоматизированный чек-лист, блокировка при отказах

**ЦБ-GCS-4**: При любых обстоятельствах команды БАС подписываются криптографически
- Актив: Аутентичность команд
- Механизм: ЭЦП на каждую команду

### Предположения безопасности

**ПБ-GCS-1**: Картографические данные актуальны и точны
**ПБ-GCS-2**: Эксплуатант передаёт корректные параметры миссии (→ ЦБ-OPS-2)
**ПБ-GCS-3**: БАС корректно интерпретирует команды (→ ЦБ-UAS-2)
**ПБ-GCS-4**: Канал связи с БАС защищён от перехвата

## 9. Система "Разработчик БАС" (DEVELOPER)

### Цели безопасности

**ЦБ-DEV-1**: При любых обстоятельствах прошивка содержит только документированный функционал
- Актив: Отсутствие закладок
- Механизм: Code review, статический анализ, воспроизводимые сборки

**ЦБ-DEV-2**: При любых обстоятельствах каждый БАС имеет уникальный неизменяемый идентификатор
- Актив: Прослеживаемость
- Механизм: Прошивка ID в OTP память

**ЦБ-DEV-3**: При любых обстоятельствах обновления прошивок подписаны ключом разработчика
- Актив: Аутентичность ПО
- Механизм: Secure boot, проверка подписи

**ЦБ-DEV-4**: При любых обстоятельствах результаты тестирования соответствуют реальным характеристикам
- Актив: Достоверность данных
- Механизм: Автоматизированное тестирование, независимая проверка

### Предположения безопасности

**ПБ-DEV-1**: Среда разработки защищена от компрометации
**ПБ-DEV-2**: Цепочка поставок компонентов контролируется
**ПБ-DEV-3**: Регулятор корректно проверяет соответствие (→ ЦБ-REG-1)

## Проверка целостности

### Покрытие критических активов

1. **Безопасность полётов** - покрыта целями UTM, UAS, GCS
2. **Экономическая безопасность** - покрыта целями OPERATOR, INSURER, AGGREGATOR
3. **Доверие в экосистеме** - покрыта целями REGULATOR, DEVELOPER
4. **Физическая безопасность** - покрыта целями DRONEPORT
5. **Информационная безопасность** - покрыта целями всех систем

### Отсутствие провисания ответственности

Каждое критическое предположение безопасности обеспечивается соответствующей целью безопасности смежной системы, что создаёт целостную распределённую концепцию безопасности.

## Механизмы контроля выполнения целей

### Автоматизированный мониторинг

Каждая цель безопасности должна иметь:
1. **Метрику** - измеримый показатель выполнения
2. **Порог** - критическое значение метрики
3. **Алерт** - оповещение при нарушении
4. **Реакцию** - автоматическое действие

### Пример для ЦБ-UTM-1

```python
class CollisionAvoidanceMonitor:
    MINIMUM_DISTANCE_M = 50
    
    def check_goal(self, uas_positions: Dict[str, Position]) -> GoalStatus:
        for uas1_id, pos1 in uas_positions.items():
            for uas2_id, pos2 in uas_positions.items():
                if uas1_id != uas2_id:
                    distance = calculate_distance(pos1, pos2)
                    if distance < self.MINIMUM_DISTANCE_M:
                        return GoalStatus.VIOLATED(
                            goal="ЦБ-UTM-1",
                            details=f"Distance {distance}m between {uas1_id} and {uas2_id}",
                            action=EmergencyManeuver(uas1_id, uas2_id)
                        )
        return GoalStatus.MAINTAINED
```

## Заключение

Доработанная система целей и предположений безопасности обеспечивает:

1. **Конструктивность** - все цели сформулированы как поддерживаемые инварианты
2. **Связность** - предположения одних систем являются целями других
3. **Полноту** - все критические активы защищены
4. **Проверяемость** - каждая цель может быть измерена и проконтролирована
5. **Автономность** - НУС работает только в автономном режиме, исключая человеческий фактор

Это создаёт основу для построения доверенной экосистемы коммерческого применения БАС.

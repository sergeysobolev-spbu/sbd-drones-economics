# ADR-007: границы доменов chaincode

| Поле | Значение |
|---|---|
| Статус | **Proposed** |
| Дата | 2026-06-28 |
| Связано | ADR-004, ADR-005, ADR-006, ADR-008 |

## Контекст

В Fabric легко превратить smart contracts в большой CRUD-реестр, где смешаны сертификаты, заказы, платежи, разрешения, телеметрия и учебные демонстрации. Это повышает сложность, размывает доверенную границу и ухудшает проверяемость СКИБ.

## Решение

Разделить домены chaincode по смыслу и зрелости:

| Домен | P1/P2 | Правило |
|---|---|---|
| Asset / drone pass | P1 | Паспорт БАС, типовой сертификат, связь с firmware. |
| Certification / firmware | P1 | Сертификация, отзыв, связь с целями безопасности. |
| Insurance | P1/P2 | Страховая запись, статус допуска, связь с заказом. |
| Order checkpoints | P1 | Только контрольные состояния заказа, без полной телеметрии. |
| Flight permission | P2 | После стабилизации ОрВД/stub и negative tests. |
| Funds distribution | P2/P3 | Только после отдельной финансовой модели и human_review. |
| Telemetry / violations | P2/P3 | Не писать целиком on-chain; использовать хэши/ссылки. |

Удаление записей заменять на `revoke`, `expire`, `supersede` или новую версию записи.

## Acceptance Criteria

- Каждый метод chaincode принадлежит одному домену.
- Для домена указан P1/P2/P3 статус.
- Нет записи полной телеметрии on-chain без ADR-009.
- Методы `Delete*` пересмотрены или явно помечены как demo-only.
- У каждого домена есть минимум один negative test.
